# 0004 · Python 3.13 as the runtime

**Status:** ✅ Accepted · **Date:** 2026-09-06

---

## Context

The brief asked for the latest Python. Managed runtimes lag upstream, so the actual constraint is
what Firebase Functions supports.

The documentation is contradictory on this point, which is worth recording so nobody re-litigates it
from the wrong page:

- `firebase.google.com/docs/functions/manage-functions` shows only `python310` and `python311`
- The **get-started** page and release notes state: *"Python versions 3.10 through 3.13 are
  supported, with 3.13 being the default runtime"*, and 3.13 is GA

The get-started page is current; the manage-functions page is stale.

## Decision

Target **Python 3.13**, runtime identifier `python313` in `firebase.json`.

## Consequences

### What this makes easier

- Current language features and performance improvements
- Longest runway before a forced runtime migration
- It's the platform default, so it's the best-tested path

### What this makes harder — the cost we're accepting

- Occasionally a library lags on 3.13 wheels; may need a version pin
- **The local machine's system Python is 3.9.** `python3` resolves to `/usr/bin/python3`. The
  Homebrew 3.13 must be selected explicitly when creating the venv, or `uv` will silently build
  against 3.9 and the failure surfaces much later, at deploy time, with an unhelpful message.

Mitigated with a `.python-version` file and an explicit interpreter path in the Makefile.

## Alternatives considered

### Python 3.11
Safest library compatibility. Rejected: no benefit, and a migration to do sooner.

### Python 3.12
Also fine. Rejected for the same reason — 3.13 is the default and GA.

## Revisit if

- A required dependency turns out not to support 3.13
